# 不安装小米程序的测试

从 Skill 根目录运行：

```powershell
python -m unittest discover -s tests -p 'test_*.py' -v
powershell.exe -NoProfile -File tests/test_windows_workflow.ps1
```

Python 测试使用合成样本：通用探测器接收不同格式和未知指纹，不按版本拒绝；固定补丁器则继续拒绝与它的固定指令/哈希证据不符的文件，并检查完整性和输出/报告冲突。两者的边界不同，均不需要分发官方 EXE。Windows 测试采用替身/隔离目录，不应启动真实安装器、程序、服务或驱动。测试所需临时目录放在执行者指定的临时工作区。

Windows 测试可以通过 `-TestDirectory` 指定目录；默认在仓库父目录下新建独立测试目录，并保留测试产物供检查。Python 测试遵循 Python 的临时目录设置，可在本次测试进程中设置 `TMPDIR`、`TEMP` 或 `TMP`，使临时文件落在指定磁盘。测试目录不应位于发布仓库内。

维护者已有合法取得且哈希匹配的原包时，还可在仓库之外用 `inspect`、`prepare`、`verify` 验证真实样本。此过程只读取和生成文件，不安装目标软件。不要把真实 EXE 或本机报告提交到仓库。

SKILL 的结构校验、单元测试和一次样本重放，只能证明各自覆盖的行为；它们不能替代不同电脑上的安装、驱动和用户功能验收。

## 0.2.0 候选适配入口验证

2026-10-16 的验证记录：

- Python 合计 33 项：32 项通过，1 项符号链接测试因本机权限不足跳过。新探测器的 14 项测试覆盖不同指纹、PE x86/x64/ARM64/ARM64EC、Mach-O 单切片/通用二进制、容器、畸形头部、原包不变和报告不覆盖；全部使用合成文件，不代表这些平台的真实产品已兼容。
- Windows PowerShell 5.1 与 PowerShell 7 各 69 项断言通过。新增原生架构检查区分 AMD64、ARM64、未知与查询失败；固定安装路线不会在未确认原生 AMD64 时调用安装器。
- 固定补丁器仍校验它唯一已验证的字节修改；它的失败不再作为整个 Skill 拒绝新构建的条件，未知候选改走分析路线。
- 本次没有执行真实安装器、客户端、服务或驱动，没有新增版本或 macOS/Windows ARM 的实机通过记录。

## 0.1.0 本地发布验证

2026-10-16 的验证记录：

- Skill 结构校验通过。
- Python 3.11：19 项测试中 18 项通过；1 项符号链接测试因当前 Windows 权限不足跳过。其余包括未知样本、额外改动、路径碰撞、硬链接、并发目标出现、既有报告和文件不被覆盖。
- Windows PowerShell 5.1 与 PowerShell 7：各 51 项断言通过。安装调用均使用替身，涵盖缺少授权/原包证明、过期或被改写基线、UAC 取消、异常退出、唯一 `/S` 参数及禁止自动重复安装。
- 对官方原包实际执行 `inspect → prepare → verify`，新副本精确复现清单中的哈希；原文件未变，仅五个预期字节改变。原包签名 Valid，兼容副本 HashMismatch。
- Windows 只读 Verify 对已安装的五个核心文件核对通过，哈希与签名均符合预期。
- 独立 agent 按用户「只做静态准备」的请求实际走通流程；修正了说明中原包签名检查的顺序与基线复用说明。

这些 Skill 验证没有再次运行小米安装器或客户端。安装调用包装本次经过模拟验证；历史实机安装与用户功能确认的证据另见 [版本证据](../references/compatibility-evidence.md)。未在另一台电脑或干净系统上安装此发布包。
