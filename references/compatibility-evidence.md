# 5.8.1.130：机制与证据

这份资料整理自 2026 年 10 月的一次静态分析与用户授权的实机验证。它是版本特定的研究记录，不代表当前最新版本或全硬件兼容认证。原始私人日志不随仓库分发。

## 文件改动

完整哈希和大小由 `profiles/5.8.1.130.json` 与确定性脚本约束。安装器副本中只有以下六字节指令范围发生替换，其中五个字节的值实际改变：

| 位置 | 内容 |
| --- | --- |
| 文件偏移 | `0xD9600` |
| RVA / 首选 VA | `0xDA200` / `0x1400DA200` |
| 原指令 | `0F 84 FB 01 00 00`，条件跳转到 `0x1400DA401` |
| 新指令 | `E9 94 00 00 00 90`，跳转到已有放行路径 `0x1400DA299`，后接 NOP |
| 实际变化的文件偏移 | `0xD9600`、`0xD9601`、`0xD9602`、`0xD9603`、`0xD9605` |
| 保持不变的前置检查 | 文件偏移 `0xD95EC` 的 `E8 8F 5D FE FF 84 C0 0F 84 09 03 00 00` |

作用域是静默安装中的 OEM/机型资格分支。交互式安装路径未修改；保留前置环境检查的调用与失败分支。前置检查完整语义尚未完全确定。其余字节必须保持一致，源文件必须不变。

命令行解析的静态证据为 `0x14009EAE0` 的 `CommandLineToArgvW` 路径；独立参数 `/S` 或 `/Silent` 设置静默模式。实际安装使用 `/S` 并以退出码 0 结束。没有验证过自定义安装目录参数，不能将 `/P` 解释成目录参数。

修改文件会使安装器的原签名呈 `HashMismatch`。安装落地后的五个主要客户端文件仍与原始安装内容逐一相同，且当时 Authenticode 验证为 Valid。这说明资格分支修改没有改变这些核心文件；不等于已经审计安装产生的所有文件。

## 已确认的安装行为

- 原始安装器在该非小米主机显示「暂不支持本设备」。
- 直接启动提取的客户端曾在 WinUI 初始化阶段失败；完整安装后主界面正常。因此「提取后直接运行」不是已经验证的替代流程。
- 使用兼容副本和 `/S` 完成了安装，运行时不需要持续注入或补丁进程。
- MiService 由既有版本 4.1.1.362 更新为 4.1.1.648；增加了 MiDeviceService，更新了相关任务和虚拟驱动配置。其服务与驱动可能由安装包中的脚本继续处理。
- 驱动脚本含旧虚拟设备卸载及新的总线、HID、显示、音频、摄像头安装步骤；无线驱动还有硬件条件分支。本 Skill 不改变这些驱动硬件条件。
- 未修改 BIOS、主板/系统身份、账号认证或账号令牌。真正登录通过官方登录窗口完成。

以上主机原先已有小米组件和虚拟驱动，不能据此断言干净系统会有相同结果。

## 功能验收的证据强度

| 功能 | 当时结论 | 证据与缺口 |
| --- | --- | --- |
| 本人账号重新登录 | 通过 | 用户自行退出后登录成功；未读取密码、验证码或令牌 |
| 手机投屏与电脑鼠标控制 | 通过 | 用户确认看到手机画面并可操作 |
| 电脑 → 手机互传 | 通过 | 用户确认收到无敏感信息的测试文本；发送端记录成功 |
| 手机 → 电脑互传 | 通过 | 用户确认图片收到；没有进行两端文件哈希对照 |
| 双向剪贴板 | 通过 | 用户分别粘贴两个方向的测试字符串并确认 |
| 平板键鼠共享、电视投屏 | 未测 | 没有相应测试设备；手机远程鼠标操作不能代替此验收 |
| 虚拟摄像头/音频/显示全部能力 | 未完成 | 出现过摄像头不可用提示，不能承诺全部可用 |
| 长期账号/信息同步 | 未充分验证 | 短期登录和跨端功能通过不等于长期令牌刷新和所有云同步项目通过 |
| 下载更高版本并完成升级 | 未测 | 「已是最新版本」回调不足以证明升级全过程 |

新用户的验收结果必须重新记录，不能把这张历史表当成其电脑已经通过的结果。
