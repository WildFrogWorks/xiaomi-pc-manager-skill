手边有小米手机，电脑却不是小米笔记本。想用电脑操作手机、传送文件、接着粘贴刚复制的文字，却在安装时遇到「暂不支持本设备」。

这个 Skill 将兼容安装的分析思路与实测流程交给 Agent：**你提供官方安装包，Agent 分析机型限制、尝试适配，再按你的授权安装与验收。** 不用先确认版本号是否在支持列表里，最终以你的电脑能否安装、启动和使用目标功能为准。

> **不设版本白名单，按实际结果验收。** 5.8.1.130 是已经实测的起点；其他版本、Windows ARM 或用户实际提供的 macOS 候选包也可进入分析。接受分析不代表已有通用补丁或保证兼容。本项目为社区工具，与小米无隶属关系。

## 把跨设备协作带到你的日常

| 你想做的事 | 已经验证的体验 |
| --- | --- |
| **在电脑上操作手机** | 查看手机投屏画面，并用电脑鼠标操作 |
| **让文件来回传递** | 电脑发送文件到手机，手机也能把文件传回电脑 |
| **复制一次，跨端接着用** | 电脑与手机双向同步剪贴板测试文字 |
| **使用自己的小米账号** | 在官方窗口退出账号后重新登录成功 |

以上体验来自一台**原先已有小米服务的非小米 Windows 11 电脑**。它们说明这条兼容路径有实机依据；你的电脑仍需逐项验收。长期账号与完整信息同步、平板键鼠共享、电视投屏及全部虚拟音视频能力尚未验证完成。

## 为什么把它交给 Skill

### 少一点摸索，多一点确定

你不用先核对版本，也不用自己寻找补丁位置。Agent 从实际文件格式、架构和机型判断逻辑入手：已知样本复用固定流程，新样本继续分析适配。**原文件保留不变，不因版本号或历史哈希不同就拒绝候选。** 已知流程不需要 REA 或 Ghidra；新构建可能需要相应分析工具。

### 从准备，一直走到真实体验

Skill 串起安装前检查、授权安装、核心文件核对和手机功能验收。它会分别记录「副本生成成功」「安装完成」和「功能实测通过」，让你知道流程到了哪一步、还有什么没验证。

### 账号由你掌握，操作有据可查

你自行在官方登录窗口输入密码与验证码；密码、验证码、账号令牌和会话数据不经 Agent。设备检查报告留在本地，默认不上传；安装前后的记录可供排查问题。需要系统授权或手机确认的环节，由你本人完成。

## 开始使用

准备好目标电脑、你自行取得的对应平台官方安装包，以及能够读取本地文件、执行命令的 Agent。**安装 Skill 本身不会安装小米软件。** 当前已验证的自动安装路径是 Windows x64；其他平台先分析，再判断是否具备安装条件。

### 1. 把 Skill 装进你的 Agent

将下面这段话复制给支持 GitHub Skill 安装的 Agent：

```text
请从 https://github.com/WildFrogWorks/xiaomi-pc-manager-skill 安装 Skill。
Skill 位于仓库根目录（路径为 .），名称为 xiaomi-pc-manager-compat-skill。
保留完整的脚本、版本清单和引用文档，阅读 SKILL.md，并按当前 Agent 的要求加载。
本次只安装 Skill，不运行小米安装器或小米程序。
```

Agent 不支持直接从 GitHub 安装时，可通过仓库的 **Code → Download ZIP** 下载，或克隆仓库。将完整目录交给 Agent，要求先阅读 `SKILL.md`；支持技能目录的 Agent 可按自身规则加载。不要只复制单个 `SKILL.md`。

### 2. 提供安装包，先做兼容准备

将下面两处路径替换成自己的实际路径，再发给 Agent：

```text
使用 xiaomi-pc-manager-compat-skill。
官方安装包路径：<安装包的完整路径>
工作目录：<用于保存兼容副本和报告的目录>
不要按版本号或历史哈希白名单拒绝，先分析平台与机型限制。
已知样本可复用固定流程；新样本请继续分析适配，说明改动和安装影响。
此阶段不要运行小米安装器或小米程序。
```

### 3. 确认安装，再连接你的手机

适配方案与副本准备完成、了解安装影响后，可以继续告诉 Agent：

```text
允许在匹配的目标电脑上安装并运行验证，使用本次准备的兼容副本。
先确认机型限制是否仍阻止安装，再确认主界面和必要组件是否正常。
小米账号由我本人登录，再引导我测试手机投屏、双向互传和双向剪贴板。
每项分别记录通过、失败或未测试，不以安装成功代替功能验收。
```

按提示完成系统授权、本人账号登录和手机端确认。Agent 会整理本次电脑上的实际结果，把已通过、失败和未测试的项目分别列出。

## 使用前请了解

| 项目 | 当前范围 |
| --- | --- |
| 候选安装包 | 不按版本白名单拒绝；未知版本进入分析，能否生成副本取决于实际逻辑 |
| 已验证快捷路径 | Windows x64 上的 5.8.1.130 精确样本；Python 3.10+、64 位 PowerShell 5.1+ |
| Windows ARM / macOS | 可接收实际候选包进行分析，暂无已验证通用补丁；需要匹配的系统、驱动和安装机制 |
| Agent 能力 | 读取 Skill、访问本地文件并执行命令；新样本还需要对应分析工具，仅能聊天的 Agent 只能指导 |
| 成功标准 | 安装、机型门槛、客户端启动、账号和设备功能分别验证；部分通过不代表全部可用 |
| 新版本与升级 | 可以在当前任务内继续适配；更高版本的完整升级流程尚未实测 |

**取消版本门槛，不等于省略目标逻辑分析。** 固定脚本仍保护自己的偏移与指令；新文件要定位实际分支，不能盲套旧补丁。macOS 与 Windows 是不同系统，应用能在 ARM 上运行也不代表相关驱动兼容。

已知 Windows 安装会涉及服务与虚拟驱动，其他候选按实际内容判断影响。修改可能破坏原签名；不要关闭系统防护，系统阻止执行时应停止并报告。安装前记录不等于系统备份，卸载也不保证恢复全部设置。需要系统级回退时，请在安装前自行准备合适的备份。

<details>
<summary><strong>它具体改了什么？</strong></summary>

已验证的 Windows 路径修改的是安装器副本中的一个**静默安装机型资格分支**，并保留前置环境检查。运行时无需持续注入，不修改 BIOS、硬件身份、账号认证或客户端核心文件。

新构建沿“定位本地机型限制 → 制作局部副本 → 安装与功能验收”的思路尝试适配，具体指令、位置和安装入口重新分析。包头识别和相似报错本身不证明补丁适用。

在上述已知 Windows 样本中，安装后的五个主要客户端文件与原始安装内容一致，且签名有效；这不代表已经审计所有安装产物。该样本的交互式安装路径未修改，固定流程使用已验证的静默安装参数；新样本需重新确认安装入口。

完整机制、修改位置与证据见 [版本证据](references/compatibility-evidence.md)。

</details>

<details>
<summary><strong>后续更新和更多设备呢？</strong></summary>

当前还没有完成更高版本下载与安装的完整验收。「已是最新版本」提示不能证明自动升级全过程可用。新版候选可以在当前任务内继续分析、适配和实机验证，无需因为版本不同就另起任务。

平板键鼠共享、电视投屏、全部虚拟音视频能力及长期账号/信息同步，不在目前已完成的验证范围内。手机投屏中的鼠标操作也不等于平板键鼠共享。详情见 [恢复与更新](references/recovery-and-updates.md)。

</details>
